# 矿权日报 Agent 技术方案

本文对应 [产品设计](./产品设计.md)，把已确认的实现方向写成可直接开工的方案。审查目标不变：约 5 分钟跑通主流程，并确认三个 MCP 服务能接到 Cursor 或 Claude Desktop。数据全链路使用 fixture，成文不调用模型 API。

## 1. 目标与边界

本次交付：

- 3 个 Python MCP 服务：`mining-news-mcp`、`mineral-pdf-mcp`、`lme-price-mcp`
- 1 个 LangGraph Agent，编排取数并输出 Markdown 简报
- `scripts/setup.ps1` 生成的 `mcp-config.json` 与 `.cursor/mcp.json`
- `RUN.md` 与一条 `docker compose up --build`

本次不做：实时抓取、付费行情、多矿区覆盖、模型 API、储量口径、价格品种和风险阈值等业务细则。

两条使用路径共用同一套服务代码和同一份 fixture：

| 路径 | 谁编排 | 结果 |
|---|---|---|
| Docker / 本地 `python -m agent` | 本仓库 Agent | 终端输出完整简报 |
| Cursor / Claude Desktop | 桌面端里的模型只负责点工具 | 单个工具返回 JSON，不生成简报 |

## 2. 总体架构

```text
                    ┌─────────────────────────────────────┐
                    │  入口                                │
                    │  Docker / python -m agent           │
                    │  或桌面端直接连 MCP                  │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │  LangGraph（仅 Docker / 本地入口）   │
                    │  parse → 并行取数 → enrich → compose │
                    └──────────────┬──────────────────────┘
                                   │ stdio 子进程
          ┌────────────────────────┼────────────────────────┐
          ▼                        ▼                        ▼
  mining-news-mcp          mineral-pdf-mcp           lme-price-mcp
  search / fetch_article   extract_resources         get_price / get_trend
          │                        │                        │
          └────────────────────────┼────────────────────────┘
                                   ▼
                            fixtures/（JSON + 演示 PDF）
                                   │
                    compose 调用 render_brief(state)
                                   ▼
                            Markdown 简报
```

Agent 在图开始前拉起三个 stdio 子进程，图结束后关闭。桌面端由 Cursor 或 Claude Desktop 按生成的配置自行拉起，Agent 不参与。

环境变量 `MINING_DATA` 未设置或值为 `fixture` 时，三个服务都读仓库内 fixture。Docker、Cursor、Claude Desktop 使用同一开关，审查看到的数据一致。

## 3. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.11+ | 服务与 Agent 共用一个虚拟环境 |
| MCP | `mcp`（FastMCP，stdio） | 工具声明短，Cursor 与 Claude Desktop 都认这套协议 |
| 编排 | `langgraph` ≥ 0.2 | 用状态图表达四步链路；并行边在汇合节点等待全部完成 |
| 成文 | `render_brief`，f-string 或 Jinja2 | 纯函数。相同状态两次调用，Markdown 相同 |
| PDF | 仓库内演示 PDF + fixture JSON | `extract_resources` 核对本地文件后返回预定储量，不访问外网 |
| 测试 | pytest | 成文测试和整图测试都调用真正的 `render_brief` |
| 运行 | venv + Docker Compose | 本机审查走 `setup.ps1`，一键审查走容器 |

依赖保持在：`mcp`、`langgraph`、`pytest`。新闻和价格在 fixture 模式下读 JSON，不引入爬虫、行情 SDK 或向量库。

## 5. 环境与 fixture

### 5.1 环境变量

| 变量 | 谁读取 | 行为 |
|---|---|---|
| `MINING_DATA` | 三个 MCP 服务 | 未设置或 `fixture`：读 `fixtures/`。其他值本次直接报错退出 |
| `BRIEF_QUERY` | `agent/main.py` | 未设置时用程序内默认句。设置时作为图的 `query` |

默认句写在 `agent/main.py`：

```text
给我生成一份关于 Pilbara 锂矿的今日简报
```

Docker 与本地入口都不把这句放进命令行参数，避免 Windows 终端编码把中文拆坏。

### 5.2 fixture 文件

`services/data.py` 用仓库根目录定位 `fixtures/`，不依赖进程启动时的当前目录。服务无论从 Cursor、Claude Desktop 还是容器里启动，都读到同一份文件。

**news.json** — `search` 的数据源。每条包含 `title`、`url`、`date`、`summary`、`keywords`。`search(query, days)` 在关键词命中且 `date` 落在窗口内时返回列表。演示数据至少两条命中 Pilbara 与锂。

**articles.json** — `fetch_article` 的数据源。键为新闻 `url`，值为 `title`、`source`、`content`。`url` 使用仓库内虚构链接（例如 `fixture://news/pilbara-lithium-1`），不发起 HTTP。

**prices.json** — `get_price` 与 `get_trend` 的数据源。按商品代码保存一段日价格，演示商品为 `lithium`。每点包含 `date`、`price`、`currency`、`unit`，并带一个 `source` 链接（同样用 `fixture://`）。

**resources.json** — `extract_resources` 的返回体。包含 Indicated 与 Inferred 各一条，字段为 `category`、`commodity`、`quantity`、`unit`、`source`。

**pilbara-lithium.pdf** — 放在仓库内的演示文件。fixture 模式下不解析 PDF 正文；工具确认该文件存在，再返回 `resources.json`。文件缺失则工具报错。这样调用链依赖仓库内文件，同时不引入 PDF 解析库。

### 5.3 工具返回形状

三个服务的工具都返回 JSON 对象（FastMCP 会序列化 dict）。

`search(query: str, days: int)`

```json
{
  "query": "Pilbara lithium",
  "days": 7,
  "items": [
    {
      "title": "...",
      "url": "fixture://news/pilbara-lithium-1",
      "date": "2026-10-08",
      "summary": "..."
    }
  ]
}
```

`fetch_article(url: str)`

```json
{
  "url": "fixture://news/pilbara-lithium-1",
  "title": "...",
  "source": "fixture://news/pilbara-lithium-1",
  "content": "..."
}
```

未知 `url` 返回 `{"url": "...", "error": "not_found"}`，由成文节点写成「正文未取得」。

`extract_resources(pdf_url: str)`

```json
{
  "pdf_url": "fixtures/pilbara-lithium.pdf",
  "source": "fixtures/pilbara-lithium.pdf",
  "resources": [
    {
      "category": "Indicated",
      "commodity": "lithium",
      "quantity": "12.4",
      "unit": "Mt",
      "source": "fixtures/pilbara-lithium.pdf"
    },
    {
      "category": "Inferred",
      "commodity": "lithium",
      "quantity": "8.1",
      "unit": "Mt",
      "source": "fixtures/pilbara-lithium.pdf"
    }
  ]
}
```

`pdf_url` 必须指向仓库内的 `fixtures/pilbara-lithium.pdf`（绝对路径或相对仓库根的路径都接受）。其他路径返回 `error: unsupported_pdf`。

`get_price(commodity: str, date: str)`

```json
{
  "commodity": "lithium",
  "date": "2026-10-08",
  "price": "980",
  "currency": "USD",
  "unit": "t",
  "source": "fixture://prices/lithium"
}
```

日期在序列中不存在时，返回不晚于该日的最近一个点，并在结果里带 `matched_date`。序列里没有任何更早的点则返回 `error: no_price`。

`get_trend(commodity: str, days: int)`

```json
{
  "commodity": "lithium",
  "days": 7,
  "source": "fixture://prices/lithium",
  "points": [
    {"date": "2026-10-02", "price": "960"},
    {"date": "2026-10-08", "price": "980"}
  ]
}
```

`days` 小于 1 时按 1 处理。点数不足时返回已有的全部点。

商品代码本次只保证 `lithium`。其他代码返回 `error: unknown_commodity`。

## 6. MCP 服务

每个服务一个 FastMCP 实例，传输固定为 stdio。

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("mining-news-mcp")

@mcp.tool()
def search(query: str, days: int) -> dict:
    ...

if __name__ == "__main__":
    mcp.run(transport="stdio")
```

对外进程入口：

| 服务名 | 模块 |
|---|---|
| `mining-news-mcp` | `python -m mining_news_mcp` |
| `mineral-pdf-mcp` | `python -m mineral_pdf_mcp` |
| `lme-price-mcp` | `python -m lme_price_mcp` |

`requirements.txt` 以可编辑方式安装这三个包和 `agent`（或把仓库根放进 `PYTHONPATH`）。`setup.ps1` 与 Docker 使用同一种安装方式。

服务进程不缓存跨调用状态。每次工具调用重新读 fixture 文件，保证改完样例数据后下次调用立即生效。

## 7. Agent 编排

编排和成文分开。图负责调用顺序和工具参数；Markdown 只从 `render_brief` 出去。图中不出现模型客户端、API key 或提示词。

### 7.1 状态

```python
class BriefState(TypedDict, total=False):
    query: str
    region: str
    commodity: str          # 工具用的代码，演示为 lithium
    commodity_label: str    # 成文用的中文，演示为 锂
    as_of: str              # YYYY-MM-DD
    news_days: int
    articles: dict          # search 的原始返回
    price: dict
    trend: dict
    bodies: list[dict]      # fetch_article 的原始返回，与 items 顺序一致
    resources: dict
    markdown: str
```

后一步只追加字段。并行取数的三个节点各写各的键（`articles`、`price`、`trend`），避免并发写同一字段。

### 7.2 图

```text
START
  → parse
  → fetch_news  ─┐
  → fetch_price  ├→ enrich
  → fetch_trend  ┘
  → compose
  → END
```

`parse` 之后三条边同时出发。`enrich` 作为汇合节点，三条分支都完成才执行。`langgraph` 0.2 及以上对这种多入边按汇合处理。

```python
graph.add_edge("parse", "fetch_news")
graph.add_edge("parse", "fetch_price")
graph.add_edge("parse", "fetch_trend")
graph.add_edge("fetch_news", "enrich")
graph.add_edge("fetch_price", "enrich")
graph.add_edge("fetch_trend", "enrich")
graph.add_edge("enrich", "compose")
```

节点函数保持很薄：读状态、做一件事、返回要合并的字段。工具名和调用顺序只写在 `agent/graph.py`。

### 7.3 parse

规则解析，默认值固定：

| 字段 | 默认 | 识别 |
|---|---|---|
| `region` | `Pilbara` | 句子中出现 `Pilbara` 则取其字面 |
| `commodity` | `lithium` | 句子中出现 `锂` 或 `lithium` |
| `commodity_label` | `锂` | 与上一行同时写出 |
| `as_of` | 运行当日（本地日期） | 句子中的 `YYYY-MM-DD`；出现 `今日` 时用运行当日 |
| `news_days` | `7` | 句子中的「N 天」；没有则用 7 |

`BRIEF_QUERY` 对不上的字段用上表默认值填上，图继续执行。本次不解析第二种矿种或第二个地区。

新闻检索词由解析结果拼接：`f"{region} {commodity}"`，例如 `Pilbara lithium`。

### 7.4 并行取数

| 节点 | 工具 | 参数 |
|---|---|---|
| `fetch_news` | `mining-news-mcp.search` | `query=f"{region} {commodity}"`，`days=news_days` |
| `fetch_price` | `lme-price-mcp.get_price` | `commodity`，`date=as_of` |
| `fetch_trend` | `lme-price-mcp.get_trend` | `commodity`，`days=news_days` |

三个节点只保存工具返回值，不在这里写简报句子。

### 7.5 enrich

1. 对 `articles["items"]` 里的每个 `url` 调用 `fetch_article`，结果按原顺序放入 `bodies`。列表为空则 `bodies` 为空列表。
2. 调用 `extract_resources`，`pdf_url` 固定为仓库内 `fixtures/pilbara-lithium.pdf` 的绝对路径。

储量 PDF 不从用户句子里解析。演示链路只有这一份 PDF。

### 7.6 compose

```python
def compose(state: BriefState) -> dict:
    return {"markdown": render_brief(state)}
```

`render_brief` 不读环境变量、不调工具、不调模型。

### 7.7 子进程生命周期

`agent/tools.py` 在一次简报运行期间持有三个 `ClientSession`。

```text
run_brief(query)
  启动三个 stdio 子进程并 initialize
  把 session 放进节点闭包
  await graph.ainvoke({"query": query})
  无论成功失败都关闭三个子进程
  返回 state["markdown"]
```

子进程命令与 `setup.ps1` 写入桌面配置的命令相同：当前解释器、`-m 模块名`、工作目录为仓库根、环境变量带上 `MINING_DATA=fixture`。这样 Docker 里的解释器和本机 venv 都能找到服务模块。

工具调用失败（进程起不来、返回 `error`、超时）时，`run_brief` 把错误写入对应状态字段并继续成文。简报对应章节显示该错误，进程仍输出 Markdown，退出码为 0。验收用的 fixture 数据把这些错误路径留空，正常审查看不到错误章节。单测可以故意传入未知商品，确认章节里出现 `error` 原文。

### 7.8 入口

`python -m agent`：

1. 读取 `BRIEF_QUERY`，未设置则用默认句
2. 调用 `run_brief`
3. 把 Markdown 打到 stdout，前后不包额外日志

Docker 的命令就是这一条。

## 8. 模板成文

`agent/render.py` 的 `render_brief(state) -> str` 按下面五个部分输出，标题固定，顺序固定。

```markdown
# {region} {commodity_label}矿简报（{as_of}）

## 新闻摘要
- {date} {title}：{summary}
  正文要点：{content 的前 120 个字符}
  来源：{url}

## 储量数据
- Indicated：{quantity} {unit}（来源：{source}）
- Inferred：{quantity} {unit}（来源：{source}）

## 价格走势
- {as_of} 价格：{price} {currency}/{unit}（来源：{source}）
- 近 {news_days} 天：{first.date} {first.price} → {last.date} {last.price}

## 风险提示
- {由下面的规则生成的句子，每条附来源}

## 来源链接
- {本节汇总上面出现过的 url / source，去重，保持首次出现顺序}
```

风险提示只用模板规则，不设业务阈值：

- 走势：比较 `trend.points` 的首尾价格。末值高于首值写「价格走高」，低于写「价格走低」，相等写「价格持平」。附价格 `source`。点数少于 2 时写「价格点不足，无法比较走势」。
- 储量：Indicated、Inferred 各自有记录则各写一句「来源给出了该级别储量」。某一级别缺失则写「来源未给出该级别储量」。附储量 `source`。
- 新闻：`items` 为空时，新闻摘要写「窗口内无匹配新闻」，风险提示加一句「新闻窗口内无匹配条目」。

某一工具结果含 `error` 时，对应章节只输出该字段，风险提示不据此推断涨跌或储量。

数字、日期、标题均原样来自工具返回，模板不换算单位、不四舍五入。

## 9. 接入配置

`scripts/setup.ps1` 做三件事：

1. 在仓库根创建 `.venv`（已存在则复用），用该环境的 Python 安装 `requirements.txt`
2. 探测 `.venv\Scripts\python.exe` 的绝对路径和仓库根绝对路径
3. 写入 `mcp-config.json` 和 `.cursor/mcp.json`

两个文件的 `mcpServers` 内容相同，每个服务一条：

```json
{
  "mcpServers": {
    "mining-news-mcp": {
      "command": "D:\\project_codes\\project_mine\\.venv\\Scripts\\python.exe",
      "args": ["-m", "mining_news_mcp"],
      "cwd": "D:\\project_codes\\project_mine",
      "env": {
        "MINING_DATA": "fixture"
      }
    }
  }
}
```

`mineral-pdf-mcp`、`lme-price-mcp` 同样结构，只改服务名和 `-m` 模块。

Claude Desktop 的用法写在 `RUN.md`：把生成的 `mcpServers` 合并进本机配置后重启。脚本不修改 Claude Desktop 的用户配置文件。

## 10. Docker

`Dockerfile` 基于 `python:3.11-slim`，工作目录 `/app`，复制仓库（含 `fixtures/` 与演示 PDF），安装依赖。启动命令：

```text
python -m agent
```

`docker-compose.yml` 只有一个服务：

```yaml
services:
  brief:
    build: .
    environment:
      MINING_DATA: fixture
```

不映射端口，不挂载会覆盖容器内 fixture 的卷。更换句子时由审查人员临时加上 `BRIEF_QUERY`，不写进默认 compose。

构建上下文包含运行所需的全部文件。容器启动后不访问外网。

## 11. 测试

测试分三层。成文相关的两层都调用仓库里的 `render_brief`，不替换成假的成文函数。

**解析** — `tests/test_parse.py`  
默认句得到 Pilbara、lithium、锂、运行当日、7 天。一句缺地区或缺矿种的 `BRIEF_QUERY` 用默认值补齐。

**成文** — `tests/test_render.py`  
手写一份取数已经完成的状态，调用 `render_brief`。断言五个章节都在，Indicated / Inferred、价格首尾、来源链接都在。同一状态调用两次，字符串相等。再覆盖空新闻、工具 `error` 两种状态，确认章节仍在且不编造涨跌。

**编排** — `tests/test_graph.py`  
在 `MINING_DATA=fixture` 下执行 `run_brief(默认句)`。断言：

- 最终状态里的 `markdown` 等于把该状态（去掉 `markdown` 后）再送进 `render_brief` 的结果
- 文中同时出现新闻标题、Indicated、Inferred、价格和来源链接

这保证成文节点走的是模板，图没有在模板之外改字。

**工具** — `tests/test_mcp_tools.py`  
以 stdio 拉起每个服务，调用 `search`、`extract_resources`、`get_price`，断言返回 JSON 含预期字段。这一层对应桌面端审查，不经过 Agent。

pytest 不需要模型 key，也不需要外网。

## 12. 验收对照

| 产品验收 | 实现位置 |
|---|---|
| `docker compose up --build` 输出含新闻摘要、储量、价格走势、风险提示、来源链接的 Markdown | `agent/main.py` → `run_brief` → `render_brief` |
| setup 后重载 Cursor，三个服务已连接 | `scripts/setup.ps1` 写入 `.cursor/mcp.json` |
| `search`、`extract_resources`、`get_price` 返回 JSON | 三个 FastMCP 工具 + `tests/test_mcp_tools.py` |
| 全程 `MINING_DATA=fixture`，无模型 key，无外网 | 服务只读 `fixtures/`；图中无模型客户端；Docker 不设网络访问 |

## 13. 实现顺序

1. `fixtures/` 与 `services/data.py`，先把样例 JSON 和演示 PDF 占位文件放进仓库
2. 三个 MCP 服务，并用 `tests/test_mcp_tools.py` 单独打通
